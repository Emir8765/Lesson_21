# 📊 Eisenhower To-Do — список дел на основе матрицы Эйзенхауэра

Консольное (CLI) приложение на Python для управления задачами по принципу
**матрицы Эйзенхауэра** — методу расстановки приоритетов, который делит
все задачи на 4 квадранта по двум осям: **важность** и **срочность**.

Построено на чистом ООП, без внешних фреймворков, с богатым консольным
интерфейсом на базе [`rich`](https://github.com/Textualize/rich) и
автоматическим сохранением данных в JSON.

## ✨ Возможности

- 🗂 **Матрица Эйзенхауэра** — все задачи распределены по 4 квадрантам
- 🎨 **Красивый цветной интерфейс** на `rich`: таблицы, панели, цветовая
  кодировка квадрантов и статусов
- ✅ Отметка задач как выполненных / невыполненных
- 🔁 Перемещение задач между квадрантами без пересоздания
- ✏️ Редактирование названия, описания и дедлайна
- 🗑 Удаление задач с подтверждением
- 📅 Дедлайны с автоматической пометкой просроченных задач
- 💾 **Автосохранение** в JSON-файл и восстановление при перезапуске
- 📐 **Адаптивная вёрстка** — интерфейс подстраивается под ширину
  терминала (в узких окнах квадранты выводятся в столбик, чтобы
  ничего не обрезалось)

## 🧭 Структура матрицы Эйзенхауэра

| | **Срочно** | **Не срочно** |
|---|---|---|
| **Важно** | 🔴 **Важно и Срочно**<br>_Делать немедленно_ | 🟢 **Важно, но Не срочно**<br>_Планировать_ |
| **Не важно** | 🟡 **Не важно, но Срочно**<br>_Делегировать_ | ⚪ **Не важно и Не срочно**<br>_Удалить / Отложить_ |

Принцип метода: задачи из верхнего левого квадранта требуют немедленных
действий, из верхнего правого — стратегического планирования, из
нижнего левого — стоит делегировать, а из нижнего правого — как
правило, можно безопасно отложить или удалить вовсе.

## 🏗 Архитектура проекта

Проект разделён на независимые модули по принципу единой
ответственности (Single Responsibility Principle):

```
eisenhower_todo/
├── models.py         # Модель данных: Task, Quadrant
├── task_manager.py   # Бизнес-логика: CRUD, фильтрация, JSON-персистентность
├── cli.py             # Презентационный слой: rich-интерфейс, ввод пользователя
├── main.py             # Точка входа в приложение
├── requirements.txt
├── .gitignore
└── README.md
```

| Модуль | Назначение |
|---|---|
| `models.py` | `Task` — dataclass-модель задачи (id, название, описание, квадрант, статус, дедлайн) с сериализацией в/из словаря. `Quadrant` — enum квадрантов с цветами и подписями. |
| `task_manager.py` | `TaskManager` — управляет коллекцией задач: добавление, удаление, редактирование, перемещение между квадрантами, фильтрация, сохранение и загрузка JSON. Не содержит логики вывода. |
| `cli.py` | `CLIInterface` — отвечает исключительно за отрисовку интерфейса (`rich`) и обработку пользовательского ввода. Делегирует все операции с данными в `TaskManager`. |
| `main.py` | Связывает `TaskManager` и `CLIInterface`, запускает основной цикл приложения. |

Такое разделение позволяет, например, безболезненно заменить
консольный интерфейс на веб- или GUI-версию, не трогая бизнес-логику.

## 🚀 Установка и запуск

### Требования
- Python 3.9 или выше
- pip

### 1. Клонируйте репозиторий

```bash
git clone https://github.com/<your-username>/eisenhower-todo.git
cd eisenhower-todo
```

### 2. (Рекомендуется) создайте виртуальное окружение

```bash
python -m venv venv

# Linux / macOS
source venv/bin/activate

# Windows
venv\Scripts\activate
```

### 3. Установите зависимости

```bash
pip install -r requirements.txt
```

### 4. Запустите приложение

```bash
python main.py
```

При первом запуске будет автоматически создан файл `tasks.json`,
в котором будут храниться все ваши задачи между сессиями.

## 🎮 Использование

После запуска вы увидите матрицу из 4 квадрантов и меню действий:

| № | Действие |
|---|---|
| 1 | Добавить задачу |
| 2 | Отметить выполнение |
| 3 | Переместить задачу между квадрантами |
| 4 | Редактировать задачу |
| 5 | Удалить задачу |
| 6 | Посмотреть детали квадранта |
| 0 | Выход |

Для большинства действий достаточно ввести **ID задачи**, который
отображается в первой колонке каждой таблицы квадранта.
